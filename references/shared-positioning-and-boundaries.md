# 共享定位机制与内容边界

本文件适用于四种模式，负责共同的定位、信任、平台和真实性规则。

## 一、IP的四个基本问题

所有输出都要帮助受众迅速理解：

1. 你是谁；
2. 你服务谁；
3. 你解决什么具体问题；
4. 为什么值得相信你。

一句话定位优先采用：

> 我是专门帮助【具体人群】，在【具体情境/阶段】解决【具体问题】，获得【结果方向】的【身份】。

结果方向不能写成未经证实的保证。

## 二、先做反定位

推荐定位前，先指出2～3个容易陷入但不适合作为主定位的方向。常见类型：

- 只讲基础知识，吸引同行或低意向泛流量；
- 只强调执行动作，被当成可比价的低价服务；
- 依赖恐吓、夸大风险或绝对承诺；
- 人群过宽，任何人都能看但没人觉得“这是为我”；
- 标签宏大，却没有真实经历和证据支撑。

反定位必须结合用户的客户、产品和信任资产，不能机械套用。

## 三、服务角色升级

高客单服务通常需要把角色从“替客户执行某项工作的人”升级为以下一种：

- 提前发现问题的人；
- 帮客户判断优先级的人；
- 把专业问题翻译成经营选择的人；
- 陪客户跨过某个发展阶段的人；
- 建立机制、降低不确定性的人。

升级后的角色仍需与真实服务能力一致。

## 四、信任资产

只从用户提供的事实中提炼：

- 从业年限；
- 身份转变；
- 服务数量或接触样本；
- 典型问题类型；
- 亲历的低谷、转折和选择；
- 方法、原则与服务边界；
- 站在客户处境进行判断的能力。

数量只能证明接触范围，不能自动推导成果。例如“处理过500个项目”不能改成“为500个客户创造成功”。

## 五、标签结构

最多使用四层：

- 主标签：客户首先用什么身份识别你；
- 副标签：你在客户身边扮演什么角色；
- 反差标签：你不采用行业里哪种常见做法；
- 记忆点标签：一条由真实经历支持的独特证据。

标签应当能在短视频里被反复证明，而不只是昵称装饰。

## 六、人生故事线

采用：

```text
过去 → 转折 → 觉醒 → 方法 → 现在 → 未来
```

- 过去：专业起点或原身份；
- 转折：身份、市场或客户变化；
- 觉醒：看见过去方法解释不了的问题；
- 方法：逐渐形成的判断步骤；
- 现在：正在帮助哪类人解决什么；
- 未来：希望客户进入什么更好状态。

故事不要求“惨”，关键是身份变化带来的认知变化。

## 七、内容到成交

内容的目标顺序：

```text
被看见 → 对号入座 → 相信判断 → 理解服务 → 低压力行动 → 诊断 → 匹配产品
```

常用低压力入口：自查清单、体检、诊断、地图、模板、问题分级。只有确实能够提供相应材料或动作时才使用。

私信承接遵循：

```text
确认用户卡点 → 收集阶段/行业/客户/产品 → 理解具体处境 → 给一个小判断 → 再决定是否推荐服务
```

不根据一句私信直接下高风险专业结论。

## 八、平台差异

- 抖音：标题和前3秒更直接，突出冲突、反常识和具体场景；节奏紧，少铺垫。
- 视频号：增加真实经历、案例类型、判断过程与老板视角，允许更完整逻辑。
- 小红书：突出避坑、经验、步骤、清单和收藏价值，标题可更结果导向。
- 朋友圈：弱化钩子感，使用观察—经历—判断—行动的自然表达。

同一核心观点要按平台重写，而不是机械复制。

## 九、真实性与专业边界

- 不编造客户、数据、对话、现场、资历和结果。
- 不将建议标题写成已经发生的真实故事。
- 用户只给方向时，用“可选表达”“案例模板”“待替换事实”标记。
- 不使用“保证爆”“一定成交”“绝对安全”等无法验证的承诺。
- 风险类内容避免制造恐慌；解释触发条件、信息限制和验证动作。
- 引用政策、平台规则或时效性数据前先核实；无法核实时避免写具体断言。
