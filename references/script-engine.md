# 爆款脚本模式

## 输入方式

接受：

- 当前选题库中的“第几类第几条”；
- 用户粘贴的选题标题；
- 用户说“你来选”。

如果编号无法在当前对话中解析，请用户粘贴标题。用户说“你来选”时：

- 有上下文：根据IP定位、平台和当前阶段选择最合适的一条；
- 无上下文：使用默认的老板/专家个人IP获客痛点题，同时明确采用了默认方向，不虚构用户行业和经历。

## 选题战略判断

正式写稿前，用2～4句话说明为什么适合当前阶段、筛选哪类人、承担哪项商业任务，以及要让客户产生什么判断。

## 脚本骨架

根据选题灵活选择下列动作，但要保留完整逻辑：

```text
点名目标客户或具体处境
→ 指出一个过时认知/异常结果
→ 解释旧方法为什么曾经可行
→ 描述阶段变化或变量增加
→ 制造核心矛盾
→ 用2～4个问题让客户自查
→ 区分表面问题与真正缺口
→ 给出新判断
→ 说明行动或升级方向
→ 金句收尾
```

故事型选题可以改为：

```text
冲突原话 → 具体现场 → 失误/转折 → 判断 → 方法或边界 → 行动
```

## 完整内容包

### 1. 封面标题

给出主标题和可选副标题。主标题简短、指向目标客户的场景或矛盾。

### 2. 前3秒钩子

一至两句，直接制造停留，不做自我介绍。

### 3. 推荐话题

给出少量与人群、问题、行业和平台匹配的话题，不堆无关热词。

### 4. 逐字稿正文

默认400～600字；复杂故事可以稍长。使用真人能顺口说出的短句和停顿，避免报告体。

### 5. 金句收尾

总结新的判断，不重复标题。

### 6. 拍摄建议

覆盖场景、人物状态、语气、停顿、机位/字幕，以及抖音和视频号的差异。

### 7. 置顶评论

补充观点或设计低压力关键词入口。没有真实承接物时，不声称“已经整理了一份资料”。

### 8. 私信承接话术

至少设计三步：

```text
确认用户卡点
→ 收集行业/阶段/客户/产品
→ 给出有限判断并请求必要信息
```

专业事实不足时不得直接下结论。

### 9. 朋友圈承接

用观察—场景—判断—行动重写，不直接复制逐字稿。

### 10. 爆款逻辑

解释这条内容怎样完成“抓停留—建信任—承接咨询”，避免用“必爆”等承诺。

### 11. 下一条系列选题

给出一条逻辑上承接当前内容、但不重复观点的下一题。

## 表达规则

- 不拍成老师上课；用同行、老板、顾问或亲历者的自然状态。
- 不把强钩子写成恐吓或夸张承诺。
- 用户没有提供案例时，不能以第一人称声称真实发生。
- 正文不急着卖产品；让私信或评论承担下一步。
- 内容包完成后可以询问哪些句子不像用户本人，以便继续调口吻。
